**最終更新**: 2026-07-18（v2 動画キャプチャデータで再評価済み）
**対象コード**: `src/phase_a/bias_estimator.py`, `src/phase_b/corrector.py`,

`scripts/signed_bias_eval.py`

## 1. フレームワーク全体像（Phase A / Phase B）

本フレームワークは、MediaPipe Pose の**視点依存バイアス**を GT なしで事後補正する
2 フェーズ構成をとる。

| フェーズ | 役割 | GT | 出力 |
|---|---|---|---|
| **Phase A（較正）** | GT 付きデータで視点×関節ごとの誤差傾向（バイアステーブル）を推定 | 使用する | `outputs/bias_tables/*.csv` |
| **Phase B（補正）** | 新規 MediaPipe 出力にカメラ位置情報だけでテーブルを適用 | 使用しない | 補正済み角度 |

補正式は全モデル共通の形をもつ:

```
x_corr = x_mp − λ · w · b
```

- `x_mp` : MediaPipe の測定値（関節角度など）
- `b`    : バイアス推定値（モデルにより粒度が異なる）
- `λ`    : 補正強度（既定 1.0、過補正抑制用）
- `w`    : 信頼度重み（§7 参照）

### カメラ特徴量

カメラ位置 (X, Y, Z) から次の特徴量を導出する（アバターは原点）:

```
D = sqrt(X² + Z²)            水平距離
φ = atan2(X, Z)              方位角（正面 = 0°）
ε = atan2(Y, D)              仰角
```

### 視点空間ビン分割（View-space Binning）

- 方位角: [−180°, +180°] を `n_az` 等分（既定 **n_az = 8**、45° 幅）
- 高さ:   Y ∈ {0.5, 1.0, 1.5, 2.0} m の 4 層
- 合計 **32 ビン**、複合キー `(height_bin, azimuth_bin)` で識別

この分割の根拠は**局所線形性仮説**である:
グローバル線形モデルは方位角に対しほぼ説明力を持たない
（v2 データで L_Shoulder の R² = 0.000）が、
ビン内の局所線形フィットは平均 R² = 0.760 に達する。
U 字型（谷型）の非線形誤差曲線を、線形近似が成立する小区間に
分割統治するのがビン分割の本質である。

## 2. Model 1: ベースライン（補正なし）

比較基準。v2 データでの補正前平均関節角 MAE は **21.3°**（known-view）、
**23.2°**（unknown-view, Y=2.0 m ホールドアウト）。

参考: v1（JPG 連続撮影、フレーム同期ずれあり）では約 26.7° だった。
動画キャプチャ化（v2）により補正前の時点で MAE が約 5° 低下している。

## 3. Model 2: 関節別定数バイアス（Joint-wise Constant）

**推定** (`estimate_joint_bias`): 関節 j ごとに全カメラの誤差平均を 1 つ取る。

```
b_j = mean(e_j)      （全カメラ・全高さ層で平均）
```

**補正** (`apply_joint_bias`): `x_corr = x_mp − λ·w·b_j`

- パラメータ数: 8（関節数）
- 特徴: 最も粗い。視点依存性を一切表現できない
- unsigned MAE をバイアスとして使うと残留 MAE ≈ 0° という
  「見かけ上完璧」な結果になるが、これは MAE の平均値を引いただけの
  数値的アーティファクトであり、個々のサンプルは過補正されている（§8 参照）

## 4. Model 3: 高さ別バイアス（Height-wise）

**推定** (`estimate_height_bias`): 関節 × カメラ高さ層（4 層）で平均。

```
b_{j,h} = mean(e_{j,h})      h ∈ {Y=0.5, 1.0, 1.5, 2.0}
```

- パラメータ数: 8 × 4 = 32
- 方位角方向の U 字構造は表現できないため、
  側面視点と正面視点が同じ補正量になる限界がある

## 5. Model 4: 視点ビン別バイアス（View-bin）← 中心モデル

**推定** (`estimate_viewbin_bias`): 関節 × 高さビン × 方位角ビンで平均。

```
b_{j,h,a} = mean(e_{j,h,a})      a ∈ {0..n_az−1}
```

- パラメータ数: 8 × 4 × 8 = 256（n_az = 8 時）
- **min_samples = 5**: ビン内サンプルが 5 未満なら bias = NaN として補正をスキップ
- U 字構造・左右非対称バイアスをビン粒度で暗黙的に吸収できる

**n_az アブレーション（v2）**:

| n_az | 較正 MAE | 検証 MAE | 汎化ギャップ |
|---|---|---|---|
| 4  | 22.32 | 22.44 | 0.116 |
| **8**  | 24.50 | 24.62 | 0.119 |
| 12 | 25.26 | 25.38 | 0.119 |
| 16 | 25.84 | 26.03 | **0.194**（過学習の兆候） |

n_az=16 で汎化ギャップが急増するため、**n_az=8 を推奨**。
また n_az=4（90° 幅）では左右非対称の境界（φ≈0°, ±180°）が
1 ビンをまたぎ、正負バイアスが相殺されてしまう。

## 6. Model 5: 線形パラメトリック補正（Linear Parametric）

**推定** (`linear_estimator.py`): ビンで区切らず、カメラ特徴量ベクトル

```
x = [1, Y, D, sin φ, cos φ, ε]ᵀ
```

に対して誤差を OLS 回帰し `ê = Xβ` を得る（関節ごとに β を推定）。

**補正** (`apply_linear_correction`): `x_corr = x_mp − λ·ê`

- パラメータ数: 8 × 6 = 48
- 滑らかな補正面が得られるが、グローバル 1 本の線形式であるため
  U 字構造を捉えられない。sin φ / cos φ 項で部分的に周期性を表現するが、
  unsigned MAE と組み合わせると Model 2 と同様の過補正アーティファクトを起こす

## 7. 信頼度重み w と補正強度 λ

**信頼度** (`_compute_reliability`):

```
w = tanh(n / 100) · exp(−std / 30)     ∈ [0, 1]
```

- ビン内サンプル数 n が多いほど、ビン内標準偏差 std が小さいほど w → 1
- 怪しいビン（少数サンプル・高ばらつき）の補正を自動的に弱める

**補正強度 λ**（v2、Model 4S での感度分析）:

| λ | \|Δθ\| 改善率 | \|Δψ\| 改善率 |
|---|---|---|
| 0.50 | 39.7% | 41.9% |
| 0.75 | 56.5% | 61.6% |
| **1.00** | **65.9%** | **74.8%** |
| 1.25 | 56.4% | 63.3% |
| 1.50 | 37.8% | 43.9% |

λ* = 1.0 が最適。λ > 1 で過補正、λ < 1 で補正不足となり対称に劣化する。
これは符号付きバイアス推定値が適切にキャリブレーションされている証拠でもある。

## 8. 符号付き vs 符号なし（本フレームワーク最大の知見）

### 問題: unsigned MAE をバイアスとして引くと過補正になる

当初のパイプラインは関節角 MAE（絶対値誤差）しか持っていなかった。
MAE は常に非負なので、「MediaPipe が過小推定する視点」でも正の値を引いてしまい、
誤差を最大 2 倍にする**系統的な過補正**が生じる。

### 解決: detailed_results.csv の符号付き方向角誤差

`32_direction_detection` が出力する per-frame 符号付き誤差
（Δθ: 仰角方向、Δψ: 方位角方向）を用いて、ビンごとの**符号付き平均**を
バイアスとする（Model 2S / 4S; `scripts/signed_bias_eval.py`）。

```
b_{j,k} = mean(δθ_{j,k})       ← 符号を保持した平均
θ_corr = θ_mp − λ · b_{j,k}
```

### v2 での結果（平均 |Δθ|、°）

| モデル | 手法 | 補正前 | 補正後 | 改善率 |
|---|---|---|---|---|
| **Model 4S** | 視点ビン・符号付き | 32.7 | **11.1** | **+65.9%** |
| Model 4U | 視点ビン・符号なし | 32.7 | 45.7 | −39.9% |
| Model 2S | 関節別定数・符号付き | 32.7 | 21.5 | +34.1% |
| Model 2U | 関節別定数・符号なし | 32.7 | 48.4 | −48.0% |

- 未知視点（Y=2.0 m）では M4S が **+72.6%**（θ）/ **+76.3%**（ψ）と、
  既知視点を上回る汎化を示す
- 関節別では Elbow 系が最大の恩恵（≈ 90% 削減）、
  Hip 系は骨盤非剛体アーティファクトの影響で ≈ 33–40% に留まる

### 補足: 局所 R² は補正効果を予測しない

「MAE フィットの局所 R² が高いビンほど補正が効く」という仮説は
**成立しない**（Pearson r = −0.27、v2）。
関節角 MAE の線形性（unsigned 集計量の予測可能性）と、
符号付き方向誤差の一貫性（ビン内で誤差の向きが揃っているか）は
視点空間の**独立した特性**である。

## 9. Model 6: 骨盤剛体制約（Pelvis Rigidity Constraint）

他モデルと異なり、テーブルを引くのではなく**座標そのものを幾何拘束で修正**する
(`src/phase_b/pelvis.py`)。

**背景**: 左右ヒップの方位角誤差 Δψ は強い逆相関（v2 で r = −0.841）を示す。
MediaPipe が骨盤を剛体として扱わず、両ヒップの奥行き z を独立に推定するためである。

**補正式**: 左右ヒップの z 差を許容値 τ でクリップする。

```
Δz' = clip(Δz, −τ, +τ)
z_L' = z_mid + Δz'/2,   z_R' = z_mid − Δz'/2
```

**τ の推定**: GT の左右ヒップ z 差の 95 パーセンタイルを用いる設計だが、
本 Unity データセットでは GT が両ヒップを単一 `Hips` ジョイントに
マッピングするため τ = 0 となる。
これは「MediaPipe の左右ヒップ奥行き差は完全にアーティファクト」であることの
理論的裏付けであり、τ = 0（両ヒップを z 中点に揃える）で逆相関は解消する。
実運用では実世界の骨盤幅に基づく τ > 0 を設定する。

## 10. モデル比較まとめ（v2 データ）

### 関節角 MAE ベース（unsigned バイアス、8 関節平均）

| モデル | Known-view 残留 MAE | 改善率 | Unknown-view 残留 MAE | 改善率 | 備考 |
|---|---|---|---|---|---|
| Baseline | 21.3° | — | 23.2° | — | |
| Model 2 | ≈ 0° | +100% | 1.9° | +94% | 過補正アーティファクト |
| Model 3 | 9.8° | +54% | 11.3° | +53% | 同上（軽度） |
| **Model 4** | **19.5°** | **+8.6%** | **21.4°** | **+8.1%** | 唯一過補正なし |
| Model 5 | ≈ −0.2° | +101% | −0.6° | +103% | 過補正アーティファクト |

### 方向角誤差ベース（signed バイアス）

| モデル | Known |Δθ| 改善 | Unknown |Δθ| 改善 |
|---|---|---|
| **Model 4S** | **+65.9%** | **+72.6%** |
| Model 2S | +34.1% | +31.8% |

**結論**: 実用構成は「**Model 4S（符号付き視点ビン、n_az=8、λ=1.0、信頼度重み付き）
＋ Model 6（骨盤剛体制約）**」である。
